# TaskSync AI

**AI駆動型タスクスケジューリング × カレンダー統合プラットフォーム**

固定予定のタイムラインと未着手タスクのプールを完全分離したデュアル画面で、本当の空き時間を浮き彫りにし、AIが学習ログから現実的な実行計画を自動生成・調整します。計画倒れを防ぐ、次世代のタスク管理体験。

## 概要

TaskSync AIは、個人の学習・作業ペースをAIが分析し、現実的なスケジュールを自動構築するタスク管理プラットフォームです。

従来のタスク・カレンダー統合ツールが抱える「タスクがカレンダー画面を圧迫し、本当の空き時間が見えなくなる」という問題を、**タイムライン（固定予定）とタスクプール（未着手タスク）の完全分離**によって解決。さらに、学習記録ログから個人の消化ペースを分析し、見積もりと実績のギャップを継続的に学習して精度を高めるAIエンジンを搭載しています。

### 対象ユーザー

- 個人開発者・エンジニア（GitHub Issue連携で開発タスクを一元管理）
- 資格試験受験者・学生（学習ログに基づくAIスケジューリング）
- 企業・教育機関（Team ライセンスで受講生・社員の進捗を可視化・管理）

## コア機能

### 1. デュアル画面レイアウト

固定予定の**タイムライン**（6:00〜21:00の時間軸）と、未着手タスクの**タスクプール**を左右に完全分離。カレンダー画面を圧迫せず、本当の空き時間を一目で把握できます。

### 2. AI自動スケジューリング

学習記録ログから個人の実際の消化ペースを分析。タスクの優先度・見積もり時間・期限を考慮し、空き時間に最適なタスクを自動配置。計画倒れを防ぐ現実的な実行計画を生成します。

- 空き時間の自動検出
- タスクの最適配置提案
- 信頼度スコア付きの提案表示
- ワンクリックで提案を適用・却下

### 3. タスク管理

- **CRUD操作** — タスクの作成・編集・削除が可能
- **優先度管理** — 緊急 / 高 / 中 / 低 の4段階
- **ステータス管理** — 未着手 / 進行中 / 完了
- **タスク分割** — 見積もり時間が60分超のタスクを自動サブタスク化
- **プロジェクト分组** — カラー付きプロジェクトでタスクをグループ化
- **タグ付け** — 自由形式のタグで柔軟な分類
- **検索・フィルタ** — タイトル検索、優先度・ステータス別フィルタ

### 4. Googleカレンダー双方向同期

OAuth認証によるGoogleカレンダー連携。予定のインポート・エクスポートを双方向で行い、重複管理を防止します。

- Googleカレンダーから予定を一括インポート
- TaskSync AIの予定をGoogleカレンダーにエクスポート
- 予定の削除も双方向で同期

### 5. GitHub連携

GitHub OAuth認証で、アサインされたIssue・PRを自動取得。ワンクリックでタスクに変換できます。

- アサイン済みオープンIssueの自動取得
- Issue → タスクのワンクリック変換
- リポジトリ一覧のキャッシュ管理

### 6. 学習ログ分析

日々の学習・作業時間を記録し、AIスケジューリングの精度向上に活用します。

- 日付・時間・カテゴリ・メモの記録
- タスクとの紐付け
- 見積もり時間と実績時間の比較分析

### 7. 生産性分析ダッシュボード

Rechartsによるデータビジュアライゼーション。

- カテゴリ別学習時間の推移
- 見積もり vs 実績の比較グラフ
- 優先度別タスク完了率
- 週次・月次の生産性サマリー

### 8. 管理者ダッシュボード（Team ライセンス）

企業・教育機関向けの管理機能。

- **ユーザー管理** — 全ユーザー一覧、管理者権限の付与・削除
- **データベース閲覧** — 主要テーブルのデータをブラウザから確認（読み取り専用）
- **スキーマ可視化** — ER図とテーブル定義の詳細表示
- **アクセス制御** — 管理者フラグによるRBAC、データベースレベルのRLSで保護

### 9. カレンダーピッカー付き日付ナビゲーション

日付移動を高速化するカレンダーポップオーバー。1日・1週間単位の移動に加え、任意の日付にジャンプできます。

| 関数 | 役割 |
|------|------|
| `ai-scheduler` | タスクの優先度・見積もり時間・空き時間を分析し、最適なスケジュールを提案。自然言語プロンプトによる対話型スケジューリングもサポート |

## データモデル

11のテーブルで構成。全テーブルで Row Level Security (RLS) を有効化し、CRUD ごとに4つのポリシーを定義。

| テーブル | 説明 |
|---------|------|
| `profiles` | ユーザープロフィール。プラン（free/pro/ultra）・管理者フラグを管理 |
| `projects` | タスクをグループ化するプロジェクト。カラー識別 |
| `tasks` | タスクの本体。優先度・ステータス・見積もり時間・GitHub Issue紐付け・親子関係 |
| `calendar_events` | カレンダーの固定予定。5タイプ（会議/業務/個人/学習/休憩）・Google同期ID |
| `study_logs` | 学習記録ログ。AIスケジューリングの精度向上に使用 |
| `google_calendar_tokens` | Googleカレンダー連携のOAuthトークン管理 |
| `github_tokens` | GitHub連携のOAuthトークン管理 |
| `github_repos` | アクセス可能なリポジトリのキャッシュ |
| `github_issues` | Issue/PRのキャッシュ。タスク変換の対象 |
| `ai_suggestions` | AIが生成したスケジュール提案。適用・却下の状態管理 |
| `ai_prompts` | ユーザーがAIアシスタントに送信したプロンプトと応答の履歴 |

## セキュリティ

### Row Level Security (RLS)

全11テーブルで RLS を有効化。ユーザーは `auth.uid() = user_id` により自分のデータのみアクセス可能。

### 管理者アクセス制御

- `profiles.is_admin` フラグによるロールベースアクセス制御（RBAC）
- `SECURITY DEFINER` 関数 `is_admin()` でデータベースレベルの権限チェック
- 管理者のみ全ユーザーのプロフィール参照・権限更新が可能
- 管理者ページはフロントエンド・データベースの二重保護

### 認証

- Supabase Auth によるメール/パスワード認証
- JWT ベースのセッション管理
- `onAuthStateChange` によるリアクティブな認証状態管理

## ローカル開発

### 前提条件

- Node.js 18+
- npm

### セットアップ

```bash

npm install

# 開発サーバーの起動
npm run dev

# プロダクションビルド
npm run build

# 型チェック
npm run typecheck
```
